Module 14: Idempotency (Safety Net)

1. The Concept

Idempotency is a fancy mathematical term that means: "Doing it multiple times has the same effect as doing it once."

In payment systems, this is critical. If I click "Pay" twice by accident, I should only be charged once.

Implementation: We require the client to send a unique ID (X-Request-Id). We remember this ID. If we see it again, we reject the request.

2. Sequence Diagram: The Happy Flow

How a unique request is processed successfully.

sequenceDiagram
    participant Client
    participant AOP as Idempotency Aspect
    participant Cache as ID Cache
    participant Service as Payment Service

    Client->>AOP: POST /payment (ID: 1001)
    AOP->>Cache: Exists(1001)?
    Cache-->>AOP: No (False)
    
    AOP->>Service: Proceed()
    Service-->>AOP: "Payment Success"
    
    AOP->>Cache: Save(1001)
    AOP->>Client: 200 OK

3. Sequence Diagram: The Duplicate Flow

What happens when the client retries the same request.

sequenceDiagram
    participant Client
    participant AOP as Idempotency Aspect
    participant Cache as ID Cache
    participant Service as Payment Service

    Client->>AOP: POST /payment (ID: 1001)
    note right of Client: ⚠️ Duplicate Retry!
    
    AOP->>Cache: Exists(1001)?
    Cache-->>AOP: Yes (True)
    
    AOP--xService: BLOCKED!
    AOP-->>Client: 409 Conflict / 500 Error

The lifecycle of a Request ID.
