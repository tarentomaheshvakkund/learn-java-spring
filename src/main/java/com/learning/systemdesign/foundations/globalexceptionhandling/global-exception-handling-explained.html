🛡️ Global Exception Handling
Explained Simply

🏢 Think of it Like a Customer Service Department

❌ OLD WAY (No Central Handler)

Each Employee Handles Complaints:

  • Sales guy handles complaints his way 📝
  • Tech guy handles them differently 🔧
  • Manager has another approach 👔
  • Everyone gives different answers! 😵
Problem:
  • Inconsistent responses
  • Some give HTML, some give errors
  • Customers confused!

✅ NEW WAY (Central Handler)

One Customer Service Desk:

  • All complaints go to ONE desk 🎯
  • Standard forms for every issue 📋
  • Same format, every time ✅
  • Professional responses 💼
Benefit:
  • Consistent JSON responses
  • Clear error messages
  • Professional API behavior
😱 The "Whitelabel Error Page" Problem

Without global exception handling, when something goes wrong:

Whitelabel Error Page
This application has no explicit mapping for /error, so you are seeing this as a fallback.

Wed Mar 20 10:15:30 IST 2024
There was an unexpected error (type=Internal Server Error, status=500).
Why This Is BAD:
  • ❌ Client expects JSON, gets HTML instead
  • ❌ Message is vague: "Internal Server Error" (what happened?)
  • ❌ Security risk: Stack traces expose internal code structure
  • ❌ Frontend can't parse this properly

💻 In Your Code

❌ Without Global Handler

@PostMapping("/users")
public ResponseEntity create() {
  try {
    userService.create();
    return ok();
  } catch (UserExistsException e) {
    return error(409, e.getMessage());
  } catch (ValidationException e) {
    return error(400, e.getMessage());
  } catch (Exception e) {
    return error(500, "Oops!");
  }
}
Every controller needs this try-catch!
Code duplication everywhere! 😱

✅ With Global Handler

// Controller - Clean!
@PostMapping("/users")
public ResponseEntity create() {
  return ok(userService.create());
  // No try-catch needed!
}

// Global Handler catches ALL errors
@RestControllerAdvice
class GlobalExceptionHandler {
  @ExceptionHandler(UserExistsException)
  handleUserExists() { ... }
}
One place handles all errors!
Controllers stay clean! 🎉

🧩 The Three Key Components
1️⃣
Custom Exception
public class UserAlreadyExistsException
    extends RuntimeException {
  // Business-specific exception
}

Throw this when username is duplicate

2️⃣
Error Response DTO
public record ErrorResponse(
  LocalDateTime timestamp,
  int status,
  String error,
  String message,
  String path
) {}

Standard format for ALL errors

3️⃣
Global Handler
@RestControllerAdvice
public class GlobalExceptionHandler {

  @ExceptionHandler(UserAlreadyExistsException.class)
  public ResponseEntity<ErrorResponse> handle(...) {
    // Convert exception → JSON
    return new ResponseEntity<>(error, 409);
  }
}

The magic interceptor that catches everything!

🎓 What is AOP (Aspect-Oriented Programming)?

Simple Analogy: Security Guard at Building Entrance

  • 🏢 Building = Your Application
  • 👮 Security Guard = @ControllerAdvice (stands at entrance)
  • 🚨 Alarm = Exception thrown
  • 📝 Incident Report = ErrorResponse JSON

How it works:

The security guard (AOP) stands BETWEEN the outside world and your building.
When any alarm (exception) goes off, the guard intercepts it BEFORE it reaches the client.
Guard fills out standard incident report (ErrorResponse) and sends it to client.
Your employees (Controllers) never need to deal with incidents!
