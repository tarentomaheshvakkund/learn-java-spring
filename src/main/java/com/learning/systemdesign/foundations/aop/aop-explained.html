Module 12: Aspect Oriented Programming (AOP)

1. The Problem: "Spaghetti Code"

Imagine you have a UserService, OrderService, and PaymentService. You want to log how long every method takes to execute for performance monitoring.

Without AOP, you would have to write this code in every single method:

public void processOrder() {
    long start = System.currentTimeMillis(); // ❌ Clutter
    
    // ... Actual Business Logic ...
    
    long end = System.currentTimeMillis();   // ❌ Clutter
    System.out.println("Execution Time: " + (end - start));
}

This is called a Cross-Cutting Concern because it "cuts across" multiple distinct modules. It leads to code duplication and makes your business logic hard to read.

2. The Solution: AOP

Aspect Oriented Programming (AOP) allows you to modularize this behavior. You write the logging logic once (in an Aspect) and "apply" it to any method you want using a simple Annotation.

💡 Real World Analogy

Think of it like a Security Guard at a building entrance.

  • The employees (Business Logic) just want to go to their desks and work.
  • They don't want to stop and write their entry time in a logbook themselves.
  • The Security Guard (Aspect) intercepts them at the door, logs the time, and then lets them proceed.

3. Key Terminology

  • Aspect: The class containing the cross-cutting logic (e.g., LoggingAspect).
  • Advice: The action taken by the aspect (e.g., "Log the time").
    • @Before: Run before the method.
    • @After: Run after the method.
    • @Around: Run around the method (before AND after). This is what we used.
  • Pointcut: A predicate that matches where the advice should run (e.g., "Any method annotated with @LogExecutionTime").
  • JoinPoint: The specific point in the execution (e.g., "The execution of OrderService.placeOrder()").

4. Our Implementation

Step 1: The Annotation

We created a marker annotation @LogExecutionTime. It does nothing by itself; it's just a flag. 

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface LogExecutionTime {}

Step 2: The Aspect

We implemented the logic primarily using the @Around advice.

@Around("@annotation(LogExecutionTime)")
public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
    long start = System.currentTimeMillis();
    
    Object proceed = joinPoint.proceed(); // ▶️ Execute the actual method
    
    long duration = System.currentTimeMillis() - start;
    logger.info(..., duration);
    return proceed;
}

Step 3: Usage

We simply applied the annotation to our Service.

@LogExecutionTime
public String placeOrder(...) { ... }

5. Benefits

  • Separation of Concerns: Business logic contains ONLY business logic.
  • DRY (Don't Repeat Yourself): Write the logging logic once, use everywhere.
  • Maintainability: Want to change the log format? Change it in one file, not 50.
