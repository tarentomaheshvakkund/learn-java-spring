3
Server Creates JWT - The Three Parts
🖥️ SERVER - Building the JWT
The server creates 3 parts:
HEADER + PAYLOAD + SIGNATURE

PART 1: HEADER (Algorithm Info)

// 1. Server creates header JSON:
{
  "alg": "HS256",
  "typ": "JWT"
}
// 2. Server Base64-encodes it:
Base64URLEncode(header) = eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
What this says: "This is a JWT token using HMAC-SHA256 algorithm"

PART 2: PAYLOAD (Your Data)

// 1. Server creates payload with your info:
{
  "sub": "john",
  "userId": 123,
  "role": "user",
  "iat": 1705334400,
  "exp": 1705420800
}
What this means:
• sub: Subject (username) = "john"
• userId: Your ID in database = 123
• role: Your role = "user"
• iat: Issued at = Jan 15, 2024 10:00 AM
• exp: Expires = Jan 16, 2024 10:00 AM (24 hours)
// 2. Server Base64-encodes it:
Base64URLEncode(payload) = eyJzdWIiOiJqb2huIiwidXNlcklkIjoxMjMsInJvbGUiOiJ1c2VyIn0
⚠️ IMPORTANT: Base64 is NOT encryption!
Anyone can decode this and read it!
NEVER put passwords or secrets here!

PART 3: SIGNATURE (Security)

// Server's SECRET KEY (only server knows this!):
SECRET_KEY = "my-super-secret-key-12345"
// Server creates signature:

data = header + "." + payload
data = "eyJhbGci...J9.eyJzdWI...In0"

signature = HMACSHA256(data, SECRET_KEY)
signature = SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
🔐 This is the MAGIC!

The signature is created using:
1️⃣ The header + payload (data)
2️⃣ The SECRET_KEY (only server has this!)
3️⃣ HMAC-SHA256 algorithm (one-way hash)

Result: A unique signature that ONLY this server can create!

FINAL JWT TOKEN

Server combines all 3 parts with dots:

HEADER:
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
PAYLOAD:
eyJzdWIiOiJqb2huIiwidXNlcklkIjoxMjMsInJvbGUiOiJ1c2VyIn0
.
SIGNATURE:
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

6
Server Validates the JWT (The Critical Part!)
🖥️ SERVER - JWT Validation Process

Validation Step 1: Split the Token

// Server splits JWT by dots:
token = "eyJhbGci...J9.eyJzdWI...In0.SflKxw...w5c"

parts = token.split(".")

header = parts[0]
payload = parts[1]
receivedSignature = parts[2]

Validation Step 2: Re-create the Signature

// Server recreates signature using its SECRET_KEY:

data = header + "." + payload
expectedSignature = HMACSHA256(data, SECRET_KEY)

// This gives us what the signature SHOULD be
🎯 The Critical Check:

Server uses the SAME process it used to create the original signature:
1. Takes header + payload
2. Applies HMAC-SHA256 with SECRET_KEY
3. Gets a signature

If nobody tampered with the token, this new signature will MATCH the original!

Validation Step 3: Compare Signatures

// Server compares:

receivedSignature = "SflKxw...w5c"
expectedSignature = "SflKxw...w5c"

if (receivedSignature === expectedSignature) {
  // ✅ VALID! Nobody tampered with it!
} else {
  // ❌ INVALID! Someone changed the token!
}
✅ SIGNATURES MATCH!

This proves:
1️⃣ Token was created by OUR server (only we have SECRET_KEY)
2️⃣ Nobody changed the payload (signature would break)
3️⃣ Token is authentic and trustworthy

Validation Step 4: Check Expiration

// Server decodes payload and checks expiration:

payload = Base64URLDecode(parts[1])

{
  "exp": 1705420800 // Expires: Jan 16, 2024 10:00 AM
}

currentTime = 1705334400 // Current: Jan 15, 2024 10:00 AM

if (currentTime < exp) {
  // ✅ Token is still valid!
} else {
  // ❌ Token expired!
}
✅ TOKEN NOT EXPIRED!
Token is still within its validity period.

Validation Step 5: Extract User Info

// Server extracts user information from payload:

{
  "sub": "john",
  "userId": 123,
  "role": "user"
}

// Now server knows:
- This request is from user: "john"
- User ID: 123
- User role: "user"
✅ ALL VALIDATIONS PASSED!

Server can now process the request safely, knowing exactly who you are!

What If a Hacker Tries to Tamper?
😈
Hacker's Attack Attempt

Hacker Intercepts Your JWT

// Hacker captures your token:
token = "eyJhbGci...J9.eyJzdWI...In0.SflKxw...w5c"

Hacker Decodes and Changes Payload

// Hacker decodes payload (easy - just Base64!):
{
  "sub": "john",
  "userId": 123,
  "role": "user" ← Hacker changes this!
}

// Hacker changes to:
{
  "sub": "john",
  "userId": 123,
  "role": "admin" ← Now john is admin!
}

Hacker Tries to Use Modified Token

// Hacker creates new token with modified payload:

header = "eyJhbGci...J9" ← Same
payload = "eyJzdWI...ImFkbWluIn0" ← CHANGED!
signature = "SflKxw...w5c" ← Old signature!

newToken = header + "." + payload + "." + signature

Server Detects the Tampering!

// Server validates:

receivedSignature = "SflKxw...w5c"

// Server recalculates signature with NEW payload:
data = header + "." + newPayload
expectedSignature = HMACSHA256(data, SECRET_KEY)
expectedSignature = "abc123...xyz" ← DIFFERENT!

if ("SflKxw...w5c" === "abc123...xyz") {
  // ✅ Valid
} else {
  // ❌ INVALID! Signatures don't match!
  throw new Error("Token tampered!");
}
❌ ATTACK FAILED!

Why it failed:
1️⃣ Hacker changed the payload
2️⃣ Old signature doesn't match new payload
3️⃣ Hacker can't create new valid signature without SECRET_KEY
4️⃣ Server detects mismatch → Rejects token

Request BLOCKED! 🚫
📚 Complete Summary

How JWT Works in Simple Steps:

1️⃣ LOGIN:
• You send username + password
• Server checks database
• Server creates JWT: header + payload + signature
• Signature = HMAC(header+payload, SECRET_KEY)
• Server sends JWT back to you

2️⃣ STORE:
• You save JWT (localStorage/memory)

3️⃣ USE:
• Every request: Include JWT in Authorization header
• Server receives request with JWT

4️⃣ VALIDATE:
• Server splits JWT into parts
• Server recreates signature: HMAC(header+payload, SECRET_KEY)
• Compares: received signature === expected signature?
• Checks expiration
• If all good → Extract username from payload
• Process request!

5️⃣ SECURITY:
• Anyone can READ payload (Base64, not encrypted)
• But only server can CREATE valid signature (has SECRET_KEY)
• Any tampering breaks signature → Server rejects it

🎯 The Core Principle:

JWT doesn't hide your data (anyone can decode it).
JWT proves AUTHENTICITY (only server can create valid signature).

It's like a diploma:
Everyone can read it, but only the university can issue a real one!
