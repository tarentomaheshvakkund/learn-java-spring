Module 9: Configuration (The Chameleon)

🦎 The Chameleon Analogy

Imagine a Chameleon.

  • In a Forest (Dev), it turns Green to blend in.
  • In a Desert (Prod), it turns Brown.

It is the same animal, but it behaves differently based on its Environment.

Your App is the Chameleon. It shouldn't change its DNA (Code) just to change its Color (Config).

1. The Problem: Hardcoding

If you write String dbUrl = "localhost:3306" in your Java code, you cannot deploy to Production.

Production has a different Database URL. Changing the code requires re-compiling and re-testing. That is Bad System Design.

2. The Solution: Profiles

Spring Profiles allow us to keep external config files. The App loads the correct one at startup.

  • application-dev.properties: Used for local testing (H2 Database).
  • application-prod.properties: Used for real users (MySQL Database).

4. How to Start the Chameleon?

You can tell the app which color (Profile) to use in 4 ways:

Method Command Usage
1. Command Line java -jar app.jar --spring.profiles.active=prod CI/CD Pipelines
2. Environment Var export SPRING_PROFILES_ACTIVE=prod Docker / Kubernetes
3. JVM Option -Dspring.profiles.active=prod Old Scripts
4. Properties spring.profiles.active=dev in file Local / Default

Note: Method 1 (Command Line) is stronger than Method 4.

5. 12-Factor App Principle

This follows the famous 12-Factor App rule for modern cloud software:

"Store config in the environment."

This ensures that the exact same code (JAR file) can run anywhere, from your laptop to the largest server in the world.
