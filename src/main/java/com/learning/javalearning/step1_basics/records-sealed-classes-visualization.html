Records, Sealed Classes & Text Blocks

Java 14+ (Text Blocks) Java 16+ (Records) Java 17+ (Sealed Classes)

📋 Records

Records are immutable data carriers that eliminate boilerplate code for simple data classes.

❌ Java 8-15 (Verbose)

public class User { private final String name; private final int age; public User(String name, int age) { this.name = name; this.age = age; } public String name() { return name; } public int age() { return age; } @Override public boolean equals(Object o) { // 15+ lines of code } @Override public int hashCode() { // 3+ lines of code } @Override public String toString() { // 1+ lines of code } }

✅ Java 16+ (Records)

public record User( String name, int age ) {} // That's it! // Auto-generates: // - Constructor // - Getters (name(), age()) // - equals() // - hashCode() // - toString() // Usage: User user = new User("Alice", 30); System.out.println(user.name());

✨ Benefits

  • Immutable by default - Thread-safe
  • 90% less code - No boilerplate
  • Perfect for DTOs - API responses, value objects
  • Pattern matching ready - Works with destructuring

🔒 Sealed Classes

Control which classes can extend or implement your types, creating closed hierarchies.

// Define sealed interface public sealed interface Shape permits Circle, Rectangle, Square { double area(); } // Only these can implement Shape public final class Circle implements Shape { private final double radius; public double area() { return Math.PI * radius * radius; } } public final class Rectangle implements Shape { private final double width, height; public double area() { return width * height; } } public final class Square implements Shape { private final double side; public double area() { return side * side; } }

✨ Benefits

  • Exhaustive switch - Compiler knows all subtypes
  • Security - Prevent unauthorized extensions
  • Domain modeling - Express precise type hierarchies
  • Better maintenance - Controlled evolution

📝 Text Blocks

Multi-line string literals that improve readability for JSON, SQL, HTML, and more.

❌ Old Way (Ugly)

String json = "{\n" + " \"name\": \"John\",\n" + " \"age\": 30,\n" + " \"city\": \"NYC\"\n" + "}"; String sql = "SELECT id, name, email\n" + "FROM users\n" + "WHERE age > 18\n" + "ORDER BY name";

✅ Text Blocks (Clean)

String json = """ { "name": "John", "age": 30, "city": "NYC" } """; String sql = """ SELECT id, name, email FROM users WHERE age > 18 ORDER BY name """;

✨ Benefits

  • Natural formatting - What you see is what you get
  • No escape hell - Quotes and newlines just work
  • Better readability - Perfect for embedded languages
  • Automatic indentation - Smart whitespace handling

🔧 Records with Custom Logic

Records aren't just data - you can add methods, validation, and custom constructors!

public record User(String name, int age) { // Compact constructor (validation) public User { if (age < 0) { throw new IllegalArgumentException( "Age cannot be negative" ); } if (name == null || name.isBlank()) { throw new IllegalArgumentException( "Name is required" ); } } // Custom methods public boolean isAdult() { return age >= 18; } public String formalName() { return "Mr/Ms. " + name; } // Static factory methods public static User anonymous() { return new User("Anonymous", 0); } } // Usage: User user = new User("Alice", 25); System.out.println(user.isAdult()); // true

🔀 Exhaustive Switch with Sealed Types

Sealed classes enable compile-time exhaustiveness checking in switch expressions.

sealed interface Result<T> permits Success, Error {} record Success<T>(T value) implements Result<T> {} record Error<T>(String message) implements Result<T> {} // Exhaustive switch - no default needed! String handle(Result<String> result) { return switch (result) { case Success<String> s -> "Success: " + s.value(); case Error<String> e -> "Error: " + e.message(); // Compiler ensures all cases covered! }; } // If you add a new type later: // record Pending<T>() implements Result<T> {} // Compiler will force you to handle it!

✨ Power Combo

  • Type safety - Can't forget a case
  • Refactoring - Add types, compiler guides you
  • No runtime surprises - Catch errors at compile time

🎨 Text Blocks Advanced Features

Text blocks come with smart features for formatting and escaping.

// Trailing backslash - no newline String oneLineSQL = """ SELECT * FROM users \ WHERE active = true \ ORDER BY name"""; // \s escape - preserve trailing spaces String formatted = """ Name: \s Age: \s City: \s """; // String interpolation with formatted() String name = "Alice"; int age = 30; String message = """ { "name": "%s", "age": %d } """.formatted(name, age); // Or use String.format() String sql = """ SELECT * FROM %s WHERE id = %d """.formatted("users", 123);

🎯 When to Use Each Feature

📋 Use Records For:

  • ✅ DTOs (Data Transfer Objects)
  • ✅ API request/response models
  • ✅ Value objects (Point, Money, etc.)
  • ✅ Configuration objects
  • ✅ Immutable data containers

🔒 Use Sealed Classes For:

  • ✅ Domain modeling (Order states, Payment types)
  • ✅ Result types (Success/Error)
  • ✅ Security - prevent unauthorized extensions
  • ✅ Exhaustive switch expressions
  • ✅ Controlled API evolution

📝 Use Text Blocks For:

  • ✅ JSON/XML/HTML embedded in code
  • ✅ SQL queries
  • ✅ Regular expressions
  • ✅ Multi-line messages/templates
  • ✅ Configuration files
