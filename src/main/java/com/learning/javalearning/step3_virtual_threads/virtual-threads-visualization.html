🎯 What are Virtual Threads?

Virtual threads are lightweight threads managed by the JVM instead of the operating system. They enable massive concurrency with simple code!

1,000,000+

✨ Key Features

  • Cheap to create - Create millions easily
  • Simple blocking code - No callbacks or reactive
  • JVM-managed - No OS thread overhead
  • Drop-in replacement - Compatible with existing code

🚀 Creating Virtual Threads

Multiple ways to create and use virtual threads.

// Method 1: Thread.ofVirtual() Thread vThread = Thread.ofVirtual() .name("my-virtual-thread") .start(() -> { System.out.println("Running in virtual thread!"); }); // Method 2: Thread.startVirtualThread() Thread.startVirtualThread(() -> { System.out.println("Quick virtual thread!"); }); // Method 3: Virtual Thread Executor try (var executor = Executors .newVirtualThreadPerTaskExecutor()) { executor.submit(() -> { System.out.println("Task 1"); }); executor.submit(() -> { System.out.println("Task 2"); }); // Auto-closes and waits for completion } // Method 4: Thread.Builder Thread.Builder builder = Thread.ofVirtual() .name("worker-", 0); Thread t1 = builder.unstarted(() -> doWork(1)); Thread t2 = builder.unstarted(() -> doWork(2)); t1.start(); t2.start();

⚖️ Platform vs Virtual Threads

🐘 Platform Threads

// Heavy - OS managed ExecutorService executor = Executors.newFixedThreadPool(200); // Limited pool size // Each thread = ~1-2 MB // Max ~few thousand threads // Context switching overhead executor.submit(() -> { // Blocks OS thread makeBlockingCall(); }); // Must manage pool carefully!
❌ Problems:
  • Limited scalability
  • High memory usage
  • Thread pool tuning needed

🦋 Virtual Threads

// Lightweight - JVM managed ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor(); // Unlimited tasks! // Each thread = ~1 KB // Millions of threads possible // No context switching overhead executor.submit(() -> { // Doesn't block OS thread makeBlockingCall(); }); // Just create threads freely!
✅ Benefits:
  • Massive scalability
  • Minimal memory usage
  • No pool management

💪 Million Threads Example

Create a million tasks effortlessly!

// This would CRASH with platform threads! // But works perfectly with virtual threads try (var executor = Executors .newVirtualThreadPerTaskExecutor()) { // Submit 1 MILLION tasks IntStream.range(0, 1_000_000).forEach(i -> { executor.submit(() -> { try { // Simulate I/O operation Thread.sleep(Duration.ofSeconds(1)); return "Task " + i + " completed"; } catch (InterruptedException e) { return "Task " + i + " interrupted"; } }); }); // All tasks run concurrently! // Completes in ~1 second, not 277 hours! } System.out.println("All 1 million tasks completed!"); // Platform threads: Would need 1 million OS threads // = ~1-2 TB of memory! 💥 // Virtual threads: Uses only a few MB of memory! ✅

📊 Resource Comparison

  • Platform threads: 1M × 2MB = 2 TB RAM ❌
  • Virtual threads: 1M × 1KB = 1 GB RAM ✅
  • Speedup: 2000× less memory!

🌐 Web Server with Virtual Threads

Handle thousands of concurrent requests effortlessly!

// Old way: Thread pool with limited threads ExecutorService executor = Executors.newFixedThreadPool(200); // Problem: Only 200 concurrent requests! // Request 201 must wait... server.setRequestHandler(request -> { executor.submit(() -> { handleRequest(request); // Blocks thread! }); }); // ===================================== // New way: Virtual threads per request ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor(); // Solution: Millions of concurrent requests! server.setRequestHandler(request -> { executor.submit(() -> { // Each request gets its own virtual thread handleRequest(request); // No problem! }); }); void handleRequest(Request req) { // Simple blocking code! String user = fetchFromDB(req.getUserId()); String data = callExternalAPI(user); String result = processData(data); sendResponse(result); // No callbacks, no reactive streams // Just plain, readable code! }

✅ Best Practices

// ✅ DO: Use for I/O-bound tasks try (var executor = Executors .newVirtualThreadPerTaskExecutor()) { // Perfect for: // - HTTP requests // - Database queries // - File I/O // - Network operations executor.submit(() -> fetchFromDatabase()); executor.submit(() -> callExternalAPI()); executor.submit(() -> readFile()); } // ❌ DON'T: Use for CPU-bound tasks // CPU-bound work should use platform threads // or parallel streams IntStream.range(0, 1000) .parallel() // Use this for CPU work .map(this::heavyComputation) .sum(); // ⚠️ AVOID: ThreadLocal with many virtual threads // ThreadLocal allocates per-thread memory // With millions of threads, this adds up! // ⚠️ AVOID: Synchronized blocks // Can pin virtual threads to platform threads // Use ReentrantLock instead

🎯 When to Use Virtual Threads

  • ✅ High concurrency I/O operations
  • ✅ Web servers handling many requests
  • ✅ Microservices with many API calls
  • ✅ Database connection pools
  • ❌ CPU-intensive computations
  • ❌ Small number of long-running tasks

⚠️ ThreadLocal Considerations

ThreadLocal can be problematic with millions of virtual threads!

// ❌ AVOID: ThreadLocal with virtual threads class UserContext { private static final ThreadLocal<User> current = new ThreadLocal<>(); // Problem: With 1M virtual threads, // this creates 1M User instances in memory! } // ✅ BETTER: Pass context explicitly void handleRequest(Request req, User user) { processWithUser(user); } // ✅ BETTER: Use Scoped Values (Java 21+) class UserContext { private static final ScopedValue<User> current = ScopedValue.newInstance(); // More efficient for virtual threads // Immutable and optimized } ScopedValue.where(UserContext.current, user) .run(() -> processRequest());

🏗️ Structured Concurrency (Preview)

Manage virtual threads lifecycle together - fail together, succeed together!

// Combine virtual threads with structured concurrency record UserData(String profile, List<Order> orders) {} UserData fetchUserData(int userId) throws InterruptedException, ExecutionException { try (var scope = new StructuredTaskScope .ShutdownOnFailure()) { // Launch concurrent tasks Future<String> profileFuture = scope.fork(() -> fetchProfile(userId)); Future<List<Order>> ordersFuture = scope.fork(() -> fetchOrders(userId)); // Wait for both (or fail if either fails) scope.join(); scope.throwIfFailed(); // Get results return new UserData( profileFuture.resultNow(), ordersFuture.resultNow() ); } } // Benefits: // - Automatic cancellation if one fails // - Clear lifecycle management // - No thread leaks // - Better error handling

🎯 Key Insight

Virtual threads are mounted on carrier threads only when they need CPU time. When they block (I/O wait), they unmount, freeing the carrier thread for others!
