Lambda Expressions

Anonymous functions that enable functional programming in Java. Lambdas let you pass behavior as data.

Syntax Evolution

❌ Before Java 8

// Anonymous inner class
Runnable r = new Runnable() {
    public void run() {
        System.out.println("Hello");
    }
};

✅ Java 8 Lambda

// One-liner!
Runnable r = () ->
    System.out.println("Hello");

// Even shorter with method ref
Runnable r = System.out::println;

Lambda Forms

// No params
() -> "hello"

// One param (parens optional)
x -> x * 2

// Multiple params
(x, y) -> x + y

// Multi-line block
(x, y) -> {
    int sum = x + y;
    return sum;
}
💡 Lambdas can only capture effectively final variables from enclosing scope.

Composition

Predicate<String> notEmpty = s -> !s.isEmpty();
Predicate<String> hasAt = s -> s.contains("@");

// Combine with .and(), .or(), .negate()
Predicate<String> validEmail =
    notEmpty.and(hasAt).and(s -> s.contains("."));

Streams API — Declarative Data Processing

Process collections functionally with a pipeline of operations. No more verbose loops!

Intermediate (Lazy)

Terminal (Triggers Execution)

collect() forEach() reduce() count() min() / max() anyMatch() findFirst() toArray() 
// Complete pipeline example
List<String> topEarners = employees.stream()
    .filter(e -> e.salary() > 50000)
    .sorted(Comparator.comparing(Employee::salary).reversed())
    .limit(5)
    .map(Employee::name)
    .collect(Collectors.toList());

// Collectors: groupingBy, partitioningBy, joining, toMap
Map<String, List<Employee>> byDept = employees.stream()
    .collect(Collectors.groupingBy(Employee::department));
⚠️ Streams are single-use — you cannot reuse a stream after a terminal operation. Streams are lazy — intermediate operations only execute when a terminal operation is called.

Optional<T>

A container that may or may not hold a value. Eliminates NullPointerException at design level.

Creating

Optional<String> a = Optional.of("hello");
Optional<String> b = Optional.empty();
Optional<String> c = Optional.ofNullable(val);
// of(null) → NullPointerException!

Extracting

MethodEmpty Behavior
orElse(default)Returns default (always evaluated)
orElseGet(supplier)Calls supplier (lazy)
orElseThrow()Throws exception
or(() → Optional)Fallback Optional (Java 9)

Transforming

// Chain operations safely
String username = Optional.ofNullable(email)
    .map(String::trim)
    .filter(s -> s.contains("@"))
    .map(s -> s.split("@")[0])
    .orElse("unknown");

// flatMap avoids Optional<Optional<T>>
Optional<String> zip = user
    .flatMap(User::address)
    .flatMap(Address::zipCode);
⚠️ Never use Optional for class fields or method parameters. Use it only for return types when a value might be absent.

Method References

Shorthand for lambdas that call a single existing method. Cleaner and more readable.

TypeLambdaMethod Ref
Statics → Integer.parseInt(s)Integer::parseInt
Bound Instances → str.concat(s)str::concat
Unbound Instances → s.toLowerCase()String::toLowerCase
Constructors → new Person(s)Person::new
// All equivalent — method ref is cleanest
names.stream().map(s -> s.toUpperCase())
names.stream().map(String::toUpperCase)  // ✅

// With streams
names.stream()
    .sorted(String::compareToIgnoreCase)
    .map(String::trim)
    .forEach(System.out::println);

// Constructor reference
String[] arr = names.stream()
    .toArray(String[]::new);
💡 Use method refs when a lambda only calls one method with no extra logic.

Default & Static Interface Methods

Java 8's solution to interface evolution — add new methods without breaking existing implementations.

Default Methods

interface Collection<T> {
    // Abstract (must implement)
    void add(T item);
    int size();

    // Default (inherited automatically)
    default boolean isEmpty() {
        return size() == 0;
    }

    // This is how Java added forEach(),
    // stream(), removeIf() to existing
    // interfaces without breaking code!
}
Inherited Overridable Has 'this'

Static Methods

interface Validator<T> {
    boolean validate(T t);

    // Static factory
    static <T> Validator<T> of(
            Predicate<T> pred) {
        return pred::test;
    }

    // Static utility (like Comparator
    // .comparing(), .naturalOrder())
    static <T> Validator<T> alwaysTrue() {
        return t -> true;
    }
}
NOT inherited NOT overridable No 'this'

Diamond Problem Resolution

interface Flyable  { default String move() { return "Flying"; } }
interface Swimmable { default String move() { return "Swimming"; } }

// Must override and choose!
class Duck implements Flyable, Swimmable {
    public String move() {
        return Flyable.super.move() + " and " + Swimmable.super.move();
    }
}

💡 Key Principles

Immutability — Strings, Optional, java.time are all immutable
Lazy Evaluation — Streams only compute when terminal op called
Composition — Chain operations: and(), or(), andThen(), compose()
Type Inference — Compiler figures out lambda parameter types
Fluent APIs — Method chaining for readable pipelines

⚠️ Common Pitfalls

Don't use Optional for fields/params
Don't reuse streams after terminal ops
Don't modify external state in lambdas
Don't use parallel streams blindly
Don't ignore orElse vs orElseGet difference
