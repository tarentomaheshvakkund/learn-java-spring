🎯 Advanced Record Patterns

Explained with Everyday Examples!

📦 Feature 1: Nested Patterns

🛒 Real Life Story: Online Shopping

🛍️

Imagine you ordered a product online. The delivery contains:
• A Box (the order)
• Inside that box is a Product
• That product has a name and price

OLD WAY: Open the box → Take out product → Read name → Read price (4 steps!)
NEW WAY: X-ray vision! See everything instantly! 🔍

How It Looks:

📦 Order
🎁 Product
Name: "Laptop"
Price: ₹50,000
➜
ONE Pattern Match:
Order(Product(name, price))
⬇️
name = "Laptop"
price = ₹50,000

Code Comparison:

❌ OLD WAY (Multiple Steps)

record Product(String name, int price) {} record Order(Product product) {} // Step 1: Check if it's an Order if (obj instanceof Order order) { // Step 2: Get the product Product p = order.product(); // Step 3: Get name String name = p.name(); // Step 4: Get price int price = p.price(); // Finally use them! System.out.println(name + ": ₹" + price); } // 😰 Too many steps!

✅ NEW WAY (One Step!)

record Product(String name, int price) {} record Order(Product product) {} // ONE step extracts EVERYTHING! 🎯 if (obj instanceof Order(Product(String name, int price))) { // name and price ready to use! System.out.println(name + ": ₹" + price); } // ✨ SO CLEAN!

🎯 Another Example: Student Report Card

Scenario: You have a student report card that contains their subject and grade
record Subject(String name, int marks) {} record ReportCard(String studentName, Subject subject) {} ReportCard card = new ReportCard( "Mahesh", new Subject("Math", 95) ); // Extract student name, subject name, and marks in ONE line! 🚀 if (card instanceof ReportCard(String student, Subject(String subName, int marks))) { System.out.println(student + " scored " + marks + " in " + subName); // Output: Mahesh scored 95 in Math }
💡 Key Point: One pattern can "see through" multiple layers and extract all values at once!

🛡️ Feature 2: Guarded Patterns (Pattern + Condition)

📧 Real Life Story: Email Filter

📬

Your email app sorts emails into folders:
• Urgent: If sender is "Boss" AND subject contains "urgent"
• Important: If sender is "Boss" (but not urgent)
• Regular: Everything else

OLD WAY: Check if email → Check sender → Check subject → Check condition (nested if-else!)
NEW WAY: Check pattern AND condition together using when! 🎯

How It Works:

1

Email Arrives

Email("Boss", "Urgent: Meeting")
2

Pattern Match with Condition

case Email(String sender, String subject) when sender.equals("Boss") && subject.contains("urgent")

Check: Is sender "Boss"? ✅ YES | Does subject contain "urgent"? ✅ YES

3

Result

✅ MATCH! → Move to Urgent folder

Code Comparison:

❌ OLD WAY (Nested If-Else)

record Email(String sender, String subject) {} String folder = ""; if (obj instanceof Email e) { if (e.sender().equals("Boss")) { if (e.subject().contains("urgent")) { folder = "Urgent"; } else { folder = "Important"; } } else { folder = "Regular"; } } // 😰 Nested if-else nightmare!

✅ NEW WAY (Guarded Patterns)

record Email(String sender, String subject) {} String folder = switch (obj) { // Pattern + Condition together! case Email(String s, String sub) when s.equals("Boss") && sub.contains("urgent") -> "Urgent"; case Email(String s, String sub) when s.equals("Boss") -> "Important"; default -> "Regular"; }; // ✨ Clean and readable!

🎯 Another Example: Movie Ticket Pricing

Scenario: Ticket prices based on age: Kids get discount, seniors get special price
record Customer(String name, int age) {} String getTicketPrice(Customer customer) { return switch (customer) { // Kids under 12: ₹100 case Customer(String name, int age) when age < 12 -> name + ": ₹100 (Kid price)"; // Seniors 60+: ₹150 case Customer(String name, int age) when age >= 60 -> name + ": ₹150 (Senior price)"; // Adults: ₹250 case Customer(String name, int age) -> name + ": ₹250 (Adult price)"; }; } // Examples: // Customer("Aarav", 8) → "Aarav: ₹100 (Kid price)" // Customer("Mahesh", 25) → "Mahesh: ₹250 (Adult price)" // Customer("Grandpa", 65) → "Grandpa: ₹150 (Senior price)"
💡 Key Point: Use when to add conditions. Pattern matches ONLY if structure AND condition are both true!

🙈 Feature 3: Underscore Pattern (_) - Ignore What You Don't Need

📱 Real Life Story: Contact List

📇

Your phone contact has:
• Name: "Mahesh"
• Phone: "9876543210"
• Email: "mahesh@example.com"
• Address: "Mumbai"

Problem: You only want to display the name. You don't care about phone, email, or address!
Solution: Use _ (underscore) to say "I know this exists, but I'm ignoring it" 🙈

What Does _ Mean?

Contact
✅ Name: "Mahesh"
❌ Phone: _ (don't care)
❌ Email: _ (don't care)
❌ Address: _ (don't care)
➜
Contact(String name, String _, String _, String _)
⬇️
Only get: name = "Mahesh"

Code Comparison:

❌ Without Underscore (Warnings!)

record Contact( String name, String phone, String email, String address ) {} case Contact(String name, String phone, String email, String address) -> "Name: " + name; // ⚠️ Compiler warnings: // "phone is never used" // "email is never used" // "address is never used" // 😰 Confusing! Did you forget?

✅ With Underscore (Clean!)

record Contact( String name, String phone, String email, String address ) {} case Contact(String name, String _, String _, String _) -> "Name: " + name; // ✅ No warnings! // Clear intent: "I'm intentionally // ignoring phone, email, address" // ✨ Clean and intentional!

🎯 Another Example: Social Media Post

Scenario: Show only author name from a post, ignore likes, comments, and timestamp
record Post( String author, String content, int likes, int comments, String timestamp ) {} String showPost(Post post) { return switch (post) { // Only care about author and content case Post(String author, String content, int _, int _, String _) -> author + ": " + content; }; } // Example: // Post("Mahesh", "Learning Java!", 50, 10, "2PM") // Output: "Mahesh: Learning Java!" // (Ignored likes=50, comments=10, timestamp="2PM")

💡 When to Use Underscore?

Use _ when:
• You know a field exists but don't need it
• You want to avoid "unused variable" warnings
• You want to make it clear you're intentionally ignoring something

Think of _ as saying: "Yeah, I know this is here, but I don't care!" 🙈

💡 Key Point: _ = "I acknowledge this exists, but I'm NOT going to use it!"

🎨 Combining All Three: Real Example

🍕 Complete Example: Food Delivery App

Scenario: A food delivery app that needs to:
• Check order details (nested: Order contains Restaurant contains Address)
• Apply delivery charges based on distance (guarded pattern)
• Ignore some fields we don't need (underscore)
// Define our data structure record Address(String city, int pincode) {} record Restaurant(String name, Address address) {} record Order(String orderId, Restaurant restaurant, int distanceKm) {} // Calculate delivery charge String calculateCharge(Order order) { return switch (order) { // Near: <5km = Free delivery! // Nested: Order → Restaurant → Address → city // Guarded: when distance < 5 // Underscore: Ignore pincode case Order( String id, Restaurant(String restName, Address(String city, int _)), int dist ) when dist < 5 -> restName + " in " + city + ": FREE delivery! 🎉"; // Medium: 5-10km = ₹40 case Order( String id, Restaurant(String restName, Address _), int dist ) when dist <= 10 -> restName + ": ₹40 delivery charge"; // Far: >10km = ₹80 case Order(String _, Restaurant(String restName, Address _), int _) -> restName + ": ₹80 delivery charge"; }; } // Test it! Order order1 = new Order( "ORD123", new Restaurant("Pizza Hut", new Address("Mumbai", 400001)), 3 // 3 km away ); System.out.println(calculateCharge(order1)); // Output: Pizza Hut in Mumbai: FREE delivery! 🎉

✨ What Happened Here?

1. Nested Pattern: We extracted city from Order → Restaurant → Address in ONE pattern!

2. Guarded Pattern: We added when dist < 5 to check distance

3. Underscore: We ignored orderId and pincode using _ because we don't need them

Result: Clean, readable code that does everything in one pattern match! 🎯

🎯 Quick Summary

📦 Nested Patterns

Extract values from nested records in ONE pattern match. Like X-ray vision - see through multiple layers at once!

🛡️ Guarded Patterns

Add conditions using when keyword. Pattern matches ONLY if both structure AND condition are true!

🙈 Underscore Pattern

Use _ to ignore values you don't need. No warnings, clean code, clear intent!

Bottom Line: Write less code, make it more readable, and handle complex data structures easily! 🚀
