Code Comparison

❌ Before Java 21

record Point(int x, int y) {} record Circle(Point center, int radius) {} Circle c = new Circle( new Point(5, 10), 25 ); // Step 1: Check type if (c instanceof Circle circle) { // Step 2: Extract center Point center = circle.center(); // Step 3: Extract x and y int x = center.x(); int y = center.y(); // Step 4: Extract radius int r = circle.radius(); // Finally use them! System.out.println("Center: " + x + "," + y); } // 😰 SO MANY STEPS!

✅ Java 21

record Point(int x, int y) {} record Circle(Point center, int radius) {} Circle c = new Circle( new Point(5, 10), 25 ); // ONE STEP! Extract EVERYTHING! 🎯 if (c instanceof Circle(Point(int x, int y), int r)) { // x, y, r are all available! System.out.println("Center: " + x + "," + y); System.out.println("Radius: " + r); } // ✨ ONE LINE TO RULE THEM ALL!

🎯 Real-World Example: Processing Shapes

record Point(int x, int y) {} record Rectangle(Point topLeft, Point bottomRight) {} void printArea(Rectangle r) { // Destructure BOTH points in one pattern! 🚀 if (r instanceof Rectangle( Point(int x1, int y1), Point(int x2, int y2) )) { int width = x2 - x1; int height = y2 - y1; System.out.println("Area: " + (width * height)); } } // Before: Would need 6+ lines to extract all 4 coordinates! // After: ONE pattern match extracts x1, y1, x2, y2! 🎉

🛡️ 2. Guarded Patterns (Pattern + Condition)

🚦 The Bouncer Analogy

Imagine a VIP club where the bouncer checks TWO things: (1) Do you have the right ticket? (2) Are you on the guest list? Guarded patterns work the same way — they check if the pattern matches AND if an additional condition is true! 🎫

💡 The when Keyword

Add conditions to your patterns using when. The pattern matches ONLY if both the structure AND the condition are satisfied!

How Guarded Patterns Work

record Person(String name, int age) {} Person person = new Person("Alice", 25); String category = switch (person) { case Person(String n, int a) when a < 18 -> n + " is a minor"; case Person(String n, int a) when a < 65 -> n + " is an adult"; case Person(String n, int _) -> n + " is a senior"; };

For Person("Alice", 25):

Person(String n, int a)
→
when a < 18
→
❌ 25 < 18? FALSE
Person(String n, int a)
→
when a < 65
→
✅ 25 < 65? TRUE!
Result: "Alice is an adult"

Code Comparison

❌ Without Guarded Patterns

String category; if (obj instanceof Person p) { if (p.age() < 18) { category = p.name() + " is a minor"; } else if (p.age() < 65) { category = p.name() + " is an adult"; } else { category = p.name() + " is a senior"; } } else { category = "Unknown"; } // 😰 Nested if-else hell!

✅ With Guarded Patterns

String category = switch (obj) { case Person(String n, int a) when a < 18 -> n + " is a minor"; case Person(String n, int a) when a < 65 -> n + " is an adult"; case Person(String n, int _) -> n + " is a senior"; default -> "Unknown"; }; // ✨ Clean, readable, expressive!

🎯 Real-World Example: Order Processing

record Order(String id, double amount, String status) {} String processOrder(Order order) { return switch (order) { // High priority: Large orders that are pending case Order(String id, double amt, String s) when amt > 1000 && s.equals("pending") -> "URGENT: Process order " + id; // Regular: Normal orders case Order(String id, double amt, String s) when s.equals("pending") -> "Process order " + id; // Already processed case Order(String id, double _, String _) -> "Order " + id + " already processed"; }; }

🙈 3. Underscore Pattern (_)

📋 The Form-Filling Analogy

When filling out a form, some fields are labeled "N/A" (Not Applicable) — you acknowledge they exist but you don't care about them. The _ underscore works the same way in patterns. It says "I know this value exists, but I'm NOT going to use it!" 📝

⚠️ Why Use Underscore?

Using _ is better than naming a variable you don't use because:
• No "unused variable" warnings
• Makes your intent clear: "I'm intentionally ignoring this"
• Cleaner code

When to Use Underscore

❌ Bad: Unused Variable

case Person(String name, int age) -> name + " (age ignored)"; // Compiler warning: // "Variable 'age' is never used" // 😰 Confusing! Did you forget to use it?

✅ Good: Explicit Ignore

case Person(String name, int _) -> name + " (age ignored)"; // No warning! // Clear intent: Age exists but we don't care // ✨ Clean and intentional!

Common Underscore Patterns

1

Ignore One Field

case Person(String name, int _) -> "Name: " + name; // I only care about the name, not the age
2

Ignore Multiple Fields

case Employee(String id, String _, int _, String _) -> id; // Only care about ID, ignore name, age, department
3

Ignore Nested Values

case Circle(Point(int x, int _), int _) -> "x: " + x; // Only care about x-coordinate, ignore y and radius
4

Catch-All Pattern

case Person(String _, int _) -> "Any person"; // Match any Person, don't care about any fields // Better than: case Person p -> "Any person"

🎯 Real-World Example: Log Processing

record LogEntry(String timestamp, String level, String message, String source) {} String formatLog(LogEntry log) { return switch (log) { // Only show errors with message case LogEntry(String _, "ERROR", String msg, String _) -> "🔴 ERROR: " + msg; // Warnings with timestamp case LogEntry(String time, "WARN", String msg, String _) -> "⚠️ " + time + ": " + msg; // Ignore info logs completely case LogEntry(String _, "INFO", String _, String _) -> ""; default -> log.toString(); }; } // Clean! No unused variable warnings! // Intent is crystal clear! ✨

🎨 Combining All Three: The Ultimate Power!

🚀 Complete Example: Shape Processor

record Point(int x, int y) {} record Circle(Point center, int radius) {} record Rectangle(Point topLeft, int width, int height) {} String analyzeShape(Object shape) { return switch (shape) { // Nested + Guarded + Underscore! case Circle(Point(int x, int y), int r) when r > 50 -> "Large circle at (" + x + "," + y + ")"; // Nested + Underscore (ignore y-coordinate) case Circle(Point(int x, int _), int r) -> "Small circle, x=" + x + ", r=" + r; // Nested + Guarded (check area) case Rectangle(Point(int _, int _), int w, int h) when w * h > 1000 -> "Large rectangle"; // Just underscore (don't care about any fields) case Rectangle(Point _, int _, int _) -> "Small rectangle"; default -> "Unknown shape"; }; } // 🎯 ONE method using ALL three features! // - Nested patterns: Circle(Point(x, y), r) // - Guarded patterns: when r > 50 // - Underscore: int _ for ignored values
