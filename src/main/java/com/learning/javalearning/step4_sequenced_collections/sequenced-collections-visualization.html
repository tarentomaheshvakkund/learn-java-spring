📦 Java 21: Sequenced Collections (JEP 431)

🤔 The Problem: Inconsistent API

❌ Before Java 21

Getting the first/last element was inconsistent across collections:

Collection Get First Get Last
List list.get(0) list.get(list.size()-1)
Deque deque.getFirst() deque.getLast()
SortedSet set.first() set.last()
LinkedHashSet set.iterator().next() 😱 ???

✅ Java 21 Solution: Unified Interface!

Now ALL ordered collections use the same methods:

// Same for List, Deque, LinkedHashSet, TreeSet... String first = collection.getFirst(); String last = collection.getLast();

🔄 Reversed Views (Zero Copy!)

The reversed() method returns a VIEW, not a copy. Changes to the view affect the original!

⚡ Same memory, different perspective!
List<Integer> nums = new ArrayList<>(List.of(1, 2, 3, 4, 5)); List<Integer> rev = nums.reversed(); // NOT a copy! // Iterate in reverse - simple and elegant for (int n : nums.reversed()) { System.out.print(n + " "); // 5 4 3 2 1 } // Modifying the view affects the original! rev.set(0, 100); // Sets nums[4] to 100

🎯 Why This Matters

🔗

Unified API

Same methods work across all ordered collections. Learn once, use everywhere!

⚡

Zero-Copy Reversal

reversed() returns a view, not a copy. Memory efficient for large collections!

📖

Readable Code

getFirst() and getLast() are self-documenting. No more get(size()-1)!

🛡️

Safe Operations

Throws NoSuchElementException on empty collections instead of IndexOutOfBounds.
